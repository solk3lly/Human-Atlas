## 1. W3C Pointer Events Level 3 & Multi-Touch / Drag-vs-Tap Disambiguation

### 1.1 Normative Event Lifecycle & Key Properties

Per the [W3C Pointer Events Level 3 Recommendation](https://www.w3.org/TR/pointerevents3/) (and the [W3C Pointer Events Editor's Draft](https://w3c.github.io/pointerevents/), sections *PointerEvent interface*, *Button states*, *The primary pointer*, *Pointer Event types*, and *Pointer capture*):

| Event | Bubbles | Cancelable | Composed | Normative Trigger & Capture Semantics |
| --- | :---: | :---: | :---: | --- |
| `pointerdown` | Yes | Yes | Yes | Fires when a pointer enters the *active buttons state* (mouse: `0 -> >=1` buttons; touch: contact with digitizer; pen: contact or button press while hovering). Canceling on a primary pointer sets `PREVENT MOUSE EVENT`, suppressing compatibility `mousedown`/`mouseup`/`mousemove` (not boundary events). Does **not** suppress browser pan/zoom—only CSS `touch-action` does. |
| `pointermove` | Yes | Yes | Yes | Fires when coordinates, pressure, tilt, contact geometry, or **chorded buttons** change without firing `pointerdown`/`pointerup`. Browsers may coalesce samples (accessible via `getCoalescedEvents()`). |
| `pointerup` | Yes | Yes | Yes | Fires when a pointer leaves the active buttons state (mouse: `>=1 -> 0` buttons; touch: contact removed). Immediately after dispatch, the UA **implicitly releases** pointer capture for `pointerId` and runs *process pending pointer capture* (`lostpointercapture`). |
| `pointercancel` | Yes | **No** | Yes | Fires when the UA suppresses a pointer stream (UA takes over pan/zoom, drag-and-drop initiation, screen orientation change, palm rejection, or exceeding hardware touch limit). Followed by `pointerout`, `pointerleave`, and **implicit release** of pointer capture (`lostpointercapture`). No `pointerup` will fire. |
| `gotpointercapture` | Yes | **No** | Yes | Fires at the capturing element once capture takes effect before subsequent pointer events. |
| `lostpointercapture` | Yes | **No** | Yes | Fires at the previously capturing element after explicit (`releasePointerCapture`) or implicit (`pointerup`, `pointercancel`, DOM removal) capture release, prior to any subsequent events for that pointer. |

Key `PointerEvent` attributes (*PointerEvent interface*, *Button states*, *The primary pointer*):

- **`pointerId`**: Unique integer per active pointer within the top-level browsing context; `-1` is reserved for events not generated by a pointing device; retired IDs may be recycled.
- **`isPrimary`**: At most one primary pointer exists **per `pointerType`** (e.g., first active touch finger). Simultaneous mouse + touch inputs each have `isPrimary === true`, so checking `isPrimary` alone cannot distinguish single-touch from multi-device or anchored-finger pinch gestures.
- **`pointerType`**: `"mouse"`, `"pen"`, `"touch"`, or `""`.
- **`button`** (state transition): `-1` (no button state change, e.g., normal move), `0` (left mouse / touch contact / pen contact), `1` (middle mouse), `2` (right mouse / pen barrel).
- **`buttons`** (bitmask of currently depressed buttons): `0` (none / hover), `1` (primary / touch / pen contact), `2` (secondary / right), `4` (auxiliary / middle).
- **Chorded button interactions** (*Button states → Chorded button interactions*): Pressing a second mouse button while another is held does **not** fire a second `pointerdown`; instead it fires `pointermove` with the newly pressed `button` and combined `buttons` bitmask (e.g., `buttons === 3`). Releasing one button while another stays pressed also fires `pointermove`, not `pointerup`; `pointerup` fires only when `buttons` transitions to `0`.
- **Implicit pointer capture** (*Pointer capture → Implicit pointer capture*): Direct-manipulation inputs (touch, stylus on touchscreen) behave as if `element.setPointerCapture(pointerId)` were called on the target element immediately before `pointerdown` listeners run.

### 1.2 Why `index.html`'s Current Single-Point `dn` Check Fails

Currently, `index.html` (lines 869–874) stores a single `[x, y]` pair on `pointerdown` and checks end-to-start distance on `pointerup`:

```js
let dn = null, last = 0;
cv.addEventListener('pointerdown', e => { dn = [e.clientX, e.clientY] });
cv.addEventListener('pointerup', e => {
  const d = dn; dn = null;
  if (!d || e.button > 0 || Math.hypot(e.clientX - d[0], e.clientY - d[1]) > 5) return;
  ...
```

This fails in four distinct ways:

1. **Two-finger pinch/pan gestures**: Finger 1 touches down (`dn = [x1, y1]`). Finger 2 touches down and **overwrites** `dn = [x2, y2]`. If Finger 2 acts as a stationary anchor (or lifts within 5 px of `[x2, y2]`) while Finger 1 pinches/pans 100 px, Finger 2's `pointerup` has `button === 0` and `hypot <= 5`, triggering an unintended structure selection (`pick`) or deselection (`pick('__all')`). Conversely, if Finger 1 lifts near `[x2, y2]`, it compares Finger 1's end coordinate against Finger 2's start coordinate.
2. **Loop-back orbit drags**: Orbiting 60 px away and dragging back within 5 px of the starting pixel yields `Math.hypot(end - start) <= 5` even though the user intentionally rotated the camera. Without tracking peak displacement (`maxDist`) or cumulative path length on `pointermove`, loop-back drags misfire as clicks.
3. **Cancelled gestures (`pointercancel`) & off-canvas releases**: When the OS/browser cancels a touch (orientation change, edge swipe, palm rejection), `pointercancel` fires and `pointerup` never arrives, leaving `dn` stale. For mouse input without capture, releasing outside `#cv` never fires `pointerup` on `#cv`, also leaving `dn` stale.
4. **Non-primary & chorded mouse buttons**: `pointerdown` does not reject `e.button !== 0`, so right-click panning overwrites `dn`. During chorded left+right presses, `pointermove` sees `buttons === 3` and `pointerup` may report `button === 0` if right was released first, falsely passing `e.button > 0`.

### 1.3 Exact Three.js r128 `OrbitControls.js` Event Architecture

Verified directly from the exact shipped script [`three@0.128.0/examples/js/controls/OrbitControls.js`](https://cdn.jsdelivr.net/npm/three@0.128.0/examples/js/controls/OrbitControls.js) (source: [mrdoob/three.js `r128`](https://github.com/mrdoob/three.js/blob/r128/examples/js/controls/OrbitControls.js)):

- **Listeners registered on `domElement` (`#cv`)**:
  ```js
  scope.domElement.addEventListener( 'contextmenu', onContextMenu );
  scope.domElement.addEventListener( 'pointerdown', onPointerDown );
  scope.domElement.addEventListener( 'wheel', onMouseWheel, { passive: false } );
  scope.domElement.addEventListener( 'touchstart', onTouchStart, { passive: false } );
  scope.domElement.addEventListener( 'touchend', onTouchEnd );
  scope.domElement.addEventListener( 'touchmove', onTouchMove, { passive: false } );
  ```
- **No `setPointerCapture` in r128**: Unlike later Three.js releases, r128 `OrbitControls` does **not** call `domElement.setPointerCapture()`.
- **Hybrid Pointer + Legacy Touch split in r128**:
  - `onPointerDown`, `onPointerMove`, and `onPointerUp` handle **only** `event.pointerType === 'mouse'` and `'pen'`, with an explicit `// TODO touch` fallthrough.
  - On mouse/pen `pointerdown`, `onMouseDown(event)` calls `event.preventDefault()`, calls `scope.domElement.focus()`, and dynamically attaches `pointermove` and `pointerup` to `scope.domElement.ownerDocument` (removing them in `onMouseUp`; r128 does **not** listen for `pointercancel` on `ownerDocument`).
  - All touch orbit/pinch/pan is handled exclusively via `touchstart` / `touchmove` / `touchend` on `domElement` (`onTouchStart` and `onTouchMove` call `event.preventDefault()`; `onTouchEnd` unconditionally resets `state = STATE.NONE` even when one finger of a two-finger gesture remains down, and r128 does not register `touchcancel`).
- **Keyboard in r128**: `listenToKeyEvents(domElement)` binds `keydown` for `ArrowLeft`/`ArrowRight`/`ArrowUp`/`ArrowDown` to **pan only** (`handleKeyDown` calls `pan()`, not orbit or zoom).

**Coexistence rules for Human Atlas's canvas gesture tracker**:

1. **Do NOT call `event.stopPropagation()`** on `#cv` pointer events, or `OrbitControls`'s `ownerDocument` mouse/pen listeners will miss `pointermove`/`pointerup` and get stuck in `STATE.ROTATE`/`STATE.PAN`.
2. **Do NOT call `cv.setPointerCapture()`** in the canvas tap/drag tracker. Instead, bind `pointerdown` on `#cv` and track `pointermove` / `pointerup` / `pointercancel` on `cv.ownerDocument` (or `window`) while any pointer is active. Reasons:
   - Matches r128 `OrbitControls`'s own `ownerDocument` mouse/pen pattern with zero capture conflict.
   - Touch inputs already receive implicit pointer capture on `#cv` per Pointer Events Level 3 and bubble to `ownerDocument`/`window`.
   - Off-canvas mouse releases are always cleaned up without leaking `activePointers`, and bounding-box checks on `pointerup` cleanly abort selection when dragging off `#cv` (WCAG SC 2.5.2).
3. Keep `#cv { touch-action: none; }` (already present in `index.html` line 264) so the browser never hijacks touch streams with native page pan/zoom.

### 1.4 Concrete Pattern: Multi-Touch & Loop-Back Safe Tap Disambiguator

```js
const TAP_TOLERANCE_MOUSE = 6; // CSS px
const TAP_TOLERANCE_TOUCH = 10; // CSS px (accounts for finger-pad roll)

const activePointers = new Map(); // pointerId -> { x0, y0, lastX, lastY, maxDist, pathLen, pointerType, valid }
let sessionTainted = false; // true if multi-touch, chorded buttons, drag, or cancel occurred

function endSessionIfIdle() {
  if (activePointers.size === 0) sessionTainted = false;
}

cv.addEventListener('pointerdown', e => {
  // Reject non-primary mouse buttons; taint session so mixed gestures cannot tap.
  const primaryPress = e.pointerType === 'mouse'
    ? (e.button === 0 && e.buttons === 1)
    : (e.button === 0 && e.isPrimary);

  activePointers.set(e.pointerId, {
    x0: e.clientX, y0: e.clientY,
    lastX: e.clientX, lastY: e.clientY,
    maxDist: 0, pathLen: 0,
    pointerType: e.pointerType,
    valid: primaryPress
  });

  if (activePointers.size > 1 || !primaryPress) {
    sessionTainted = true;
  }
});

window.addEventListener('pointermove', e => {
  const p = activePointers.get(e.pointerId);
  if (!p) return;

  // Detect chorded mouse buttons (e.g., left + right pressed together)
  if (e.pointerType === 'mouse' && (e.buttons !== 1 || e.button !== -1)) {
    p.valid = false;
    sessionTainted = true;
    return;
  }

  const samples = typeof e.getCoalescedEvents === 'function' ? e.getCoalescedEvents() : [e];
  const pts = samples.length ? samples : [e];
  for (const s of pts) {
    const step = Math.hypot(s.clientX - p.lastX, s.clientY - p.lastY);
    p.pathLen += step;
    p.lastX = s.clientX;
    p.lastY = s.clientY;
    const fromStart = Math.hypot(s.clientX - p.x0, s.clientY - p.y0);
    if (fromStart > p.maxDist) p.maxDist = fromStart;
  }

  const tol = p.pointerType === 'touch' ? TAP_TOLERANCE_TOUCH : TAP_TOLERANCE_MOUSE;
  if (p.maxDist > tol || p.pathLen > tol * 2) {
    p.valid = false;
    sessionTainted = true;
  }
});

window.addEventListener('pointerup', e => {
  const p = activePointers.get(e.pointerId);
  if (!p) return;
  activePointers.delete(e.pointerId);

  const tol = p.pointerType === 'touch' ? TAP_TOLERANCE_TOUCH : TAP_TOLERANCE_MOUSE;
  const endDist = Math.hypot(e.clientX - p.x0, e.clientY - p.y0);
  const rect = cv.getBoundingClientRect();
  const insideCanvas = e.clientX >= rect.left && e.clientX <= rect.right &&
                       e.clientY >= rect.top && e.clientY <= rect.bottom;

  const isCleanTap = !sessionTainted &&
    activePointers.size === 0 &&
    p.valid &&
    e.button === 0 &&
    p.maxDist <= tol &&
    endDist <= tol &&
    insideCanvas;

  endSessionIfIdle();
  if (isCleanTap) handleCanvasSelect(e);
});

function abortPointer(e) {
  if (!activePointers.has(e.pointerId)) return;
  activePointers.delete(e.pointerId);
  sessionTainted = true;
  endSessionIfIdle();
}
window.addEventListener('pointercancel', abortPointer);
window.addEventListener('blur', () => { activePointers.clear(); sessionTainted = false; });
```

### 1.5 Pointer Capture Lifecycle for Custom Resize Handles (`#rz1`, `#rz2`)

Current `drag()` in `index.html` (line 882) attaches `pointermove`/`pointerup` without filtering `pointerId`, without checking `e.button === 0`, without catching `setPointerCapture` exceptions, and without cleaning up on `pointercancel` or `lostpointercapture`.

Per Pointer Events Level 3 (*Setting pointer capture*, *Releasing pointer capture*, *Implicit release of pointer capture*):

- `setPointerCapture(pointerId)` throws `NotFoundError` if `pointerId` is not active and `InvalidStateError` if the element is disconnected or Pointer Lock is active; it is a silent no-op if the pointer is not in the active buttons state.
- `releasePointerCapture(pointerId)` throws `NotFoundError` if `pointerId` is not active (e.g., if called after implicit release on `pointerup`/`pointercancel`). Always guard explicit release with `el.hasPointerCapture(id)`.
- Using `lostpointercapture` as a guaranteed cleanup hook—alongside `pointerup` and `pointercancel`—prevents stuck drags even if the element is hidden (e.g., responsive breakpoint or `.sc`/`.ic` collapse) or capture is forcibly revoked by the UA.

```js
function bindResizeDrag(handle, onMove, onEnd) {
  let activeId = null;

  function finish(ev) {
    if (activeId === null || (ev && ev.pointerId !== activeId)) return;
    const id = activeId;
    activeId = null;
    handle.removeEventListener('pointermove', onPointerMove);
    handle.removeEventListener('pointerup', finish);
    handle.removeEventListener('pointercancel', finish);
    handle.removeEventListener('lostpointercapture', finish);
    try {
      if (handle.hasPointerCapture(id)) handle.releasePointerCapture(id);
    } catch (_) { /* pointer already inactive */ }
    if (onEnd) onEnd();
  }

  function onPointerMove(ev) {
    if (ev.pointerId !== activeId) return;
    onMove(ev);
  }

  handle.addEventListener('pointerdown', e => {
    if (activeId !== null) return; // ignore secondary simultaneous pointers
    if (e.pointerType === 'mouse' && e.button !== 0) return;
    e.preventDefault();
    activeId = e.pointerId;
    try { handle.setPointerCapture(activeId); } catch (_) { /* fallback still safe if capture denied */ }
    handle.addEventListener('pointermove', onPointerMove);
    handle.addEventListener('pointerup', finish);
    handle.addEventListener('pointercancel', finish);
    handle.addEventListener('lostpointercapture', finish);
  });
}
```

## 2. WebGL / Three.js r128 Binary Loader Robustness & Safe Disposal

### 2.1 Explicit Little-Endian Decoding (`DataView`) vs Host-Endian `TypedArray`

Human Atlas packs quantized vertices and triangle indices as little-endian 16-bit unsigned integers (`tools/import_hra.py`, lines 102–105: `astype('<u2').tobytes()`), while `index.html` (line 701) currently decodes via:

```js
function dec(b) {
  const s = atob(b), u = new Uint8Array(s.length);
  for (let i = 0; i < s.length; i++) u[i] = s.charCodeAt(i);
  return new Uint16Array(u.buffer);
}
```

Normative behavior per [ECMA-262](https://tc39.es/ecma262/multipage/):

- **Host-endian TypedArrays** ([§25.1.3.16 `GetValueFromBuffer`](https://tc39.es/ecma262/multipage/structured-data.html#sec-getvaluefrombuffer)): When `isLittleEndian` is omitted (which all `TypedArray` element reads do), the runtime sets `isLittleEndian` to `agentRecord.[[LittleEndian]]`—the host CPU byte order. On big-endian hosts, `new Uint16Array(u.buffer)` byte-swaps every vertex coordinate and triangle index.
- **Unaligned / odd-length crash** ([§23.2.5.1.3 `InitializeTypedArrayFromArrayBuffer`](https://tc39.es/ecma262/multipage/indexed-collections.html#sec-initializetypedarrayfromarraybuffer)): Constructing `new Uint16Array(buffer)` when `buffer.byteLength % 2 !== 0` throws a `RangeError`.
- **Explicit byte-order `DataView` reads** ([§25.3.4.14 `DataView.prototype.getUint16(byteOffset [, littleEndian])`](https://tc39.es/ecma262/multipage/structured-data.html#sec-dataview.prototype.getuint16) and [§25.3.4.8 `DataView.prototype.getFloat32(byteOffset [, littleEndian])`](https://tc39.es/ecma262/multipage/structured-data.html#sec-dataview.prototype.getfloat32)): `littleEndian` **defaults to `false` (big-endian)** if omitted; passing `true` guarantees exact IEEE-754 float32 / uint16 little-endian decoding regardless of host endianness, and `DataView` permits arbitrary byte offsets.
- **WebGL upload note**: Reading little-endian words via `dv.getUint16(byteOffset, true)` and writing the resulting numeric values into per-mesh `Float32Array` (positions) and `Uint16Array` (indices) stores each number in host representation via `SetValueInBuffer`, which is the exact format expected by `THREE.BufferAttribute` and WebGL `bufferData` (`ELEMENT_ARRAY_BUFFER`). It also eliminates the redundant full-blob `Uint16Array` view and `w.slice(...)` allocation.

### 2.2 Pre-Allocation Binary, Base64, and Metadata Validation

Per [WHATWG HTML `atob(data)`](https://html.spec.whatwg.org/multipage/webappapis.html#atob) and [WHATWG Infra *forgiving-base64 decode*](https://infra.spec.whatwg.org/#forgiving-base64-decode):
- `atob()` strips ASCII whitespace (`\t \n \f \r SP`), strips 1–2 trailing `=` padding characters when divisible by 4, throws `DOMException("InvalidCharacterError")` if `length % 4 === 1` or any character is outside `[A-Za-z0-9+/]`, and **silently discards trailing unused bits** (e.g., `"YQ"` and `"YR"` both decode to `"a"`).

Per [Khronos WebGL 1.0 §6.5 *Enabled Vertex Attributes and Range Checking*](https://registry.khronos.org/webgl/specs/latest/1.0/#6.5) and Three.js r128 [`BufferGeometry.computeVertexNormals()`](https://github.com/mrdoob/three.js/blob/r128/src/core/BufferGeometry.js):
- An out-of-range face index (`idx >= nv`) causes `computeVertexNormals()` to read `undefined` from the position `Float32Array`, propagating `NaN` into triangle vertex normals before GPU upload; at draw time, WebGL `drawElements` may either raise `GL_INVALID_OPERATION` and render nothing or substitute arbitrary/zero values.

**Strict pre-allocation validation pipeline** (run completely before constructing any `THREE.BufferGeometry`, `THREE.Material`, or `THREE.Mesh`):

1. **Envelope & format/version check**: Verify `L && typeof L === 'object'`, `typeof L.b === 'string'`, `L.m && typeof L.m === 'object'`. If a format identifier/version field is added to the JSON schema (recommended: `fmt: 'ha-mesh-v1'`, `v: 1`), validate exact match and reject unsupported versions early.
2. **Schema / generation hash check (`BL[k]` ↔ `data/atlas_<k>.json`)**: Store a deterministic content/ordinal digest (e.g., `hash` derived from ordered mesh names + counts) in both `BL[k]` inside `index.html` and `data/atlas_<k>.json`, and fail loudly if `BL[k].hash && L.m.hash !== BL[k].hash`. This catches stale CDN/browser caches where `index.html` and `data/atlas_<k>.json` are out of sync and `item.p` ordinals would highlight the wrong anatomy structures.
3. **Quantization bounds (`mn`, `sc`)**: Verify `Array.isArray(mn) && mn.length === 3 && mn.every(Number.isFinite)` and `Number.isFinite(sc) && sc > 0` (note: `tools/import_hra.py` computes `65535 / scale`, so `sc <= 0` indicates corrupt or degenerate data; if single-point/zero-extent meshes must ever be supported, explicitly handle `sc === 0` without dividing by zero rather than silently propagating `NaN`).
4. **Base64 decode & byte-length check**: Wrap `atob(L.b)` in `try/catch`; reject non-canonical/whitespace-corrupted strings if strict check is desired (`/^[A-Za-z0-9+/]*={0,2}$/` and `L.b.length % 4 === 0`). Verify `bytes.byteLength % 2 === 0` and compute `totalWords = bytes.byteLength / 2`.
5. **Metadata tuple & offset validation**: Verify `Array.isArray(meta) && meta.length > 0`. For each tuple `m` at index `mi`:
   - `Array.isArray(m) && m.length >= 5`, `typeof m[0] === 'string' && m[0].length > 0`.
   - `nv = m[1]`, `nf = m[2]`, `vo = m[3]`, `fo = m[4]` are all `Number.isSafeInteger(...)` and `>= 0`.
   - `nv > 0 && nv <= 65535` (required for `Uint16Array` indexing; Three.js r128 `BufferGeometry.setIndex` uses `Uint16BufferAttribute` for `<= 65535`), `nf > 0`.
   - Bounds within buffer: `vo + nv * 3 <= totalWords` and `fo + nf * 3 <= totalWords` (and optionally enforce contiguous layout `vo === expectedVo`, `fo === expectedFo`, `finalFaceEnd === totalWords`, matching `tools/test_atlas_data.py` lines 25–32).
6. **Vertex index range validation**: While decoding each mesh's face indices via `dv.getUint16((fo + i) * 2, true)`, assert `idx < nv` for every index `0 <= i < nf * 3`.
7. **Sidebar `BL[k]` ordinal coverage & bounds check**: Verify every ordinal `p` referenced in `BL[k].g[].items[].p` satisfies `Number.isSafeInteger(p) && p >= 0 && p < meta.length`. Additionally check full bijection (`ownedSet.size === meta.length`, matching `tools/test_atlas_data.py` lines 22–23) so no sidebar item resolves to `MESH[k][p] === undefined` in `visibleForSide()` or `pick()`.

### 2.3 Atomic Scene Commit, Safe GPU Disposal, and Stale Async Cancellation

Per Three.js r128's official guide [*How to dispose of objects*](https://github.com/mrdoob/three.js/blob/r128/docs/manual/en/introduction/How-to-dispose-of-objects.html) and source [`BufferGeometry.js`](https://github.com/mrdoob/three.js/blob/r128/src/core/BufferGeometry.js) / [`Material.js`](https://github.com/mrdoob/three.js/blob/r128/src/materials/Material.js):
- Removing a `THREE.Mesh` from `scene` does **not** free its GPU `WebGLBuffer`s or compiled shader programs. Each allocated `BufferGeometry` and `Material` must explicitly have `.dispose()` invoked (and `Texture.dispose()` if textures are ever attached).
- In current `index.html` (line 719), `scene.add(me)` runs inside the per-mesh loop before the layer finishes. Any error mid-layer leaks all previously created meshes in `scene` and GPU memory, and retrying duplicates them.

Per [WHATWG DOM `AbortController` / `AbortSignal`](https://dom.spec.whatwg.org/#interface-abortcontroller) and [WHATWG Fetch](https://fetch.spec.whatwg.org/#fetch-method):
- Passing `{ signal: controller.signal }` to `fetch()` cancels in-flight network transfers (critical for large layers like `atlas_vsKa.json` at 16 MB) and rejects with `DOMException` (`err.name === 'AbortError'`).
- **Important Human Atlas nuance**: `ensure(k)` also triggers background `loadLayer('rangka')` for skeletal context (`index.html` line 843). Keep primary layer fetches cancellable via an active-layer `AbortController` + monotonic sequence token (`loadSeq`), while keeping the shared `'rangka'` context fetch independent so switching from `otot` to `saraf` does not abort a needed `'rangka'` download.

```js
function disposeMeshes(meshes) {
  for (const me of meshes) {
    if (me.parent) me.parent.remove(me);
    if (me.geometry) me.geometry.dispose();
    if (Array.isArray(me.material)) me.material.forEach(m => m.dispose());
    else if (me.material) me.material.dispose();
  }
}

function parseAndBuildLayer(k, L, signal) {
  const { dv, mn, sc, meta } = validateAtlasPayload(k, L); // throws before any GPU/Three allocation
  const built = [];
  try {
    for (let mi = 0; mi < meta.length; mi++) {
      if (signal && signal.aborted) throw new DOMException('Aborted', 'AbortError');
      const [name, nv, nf, vo, fo] = meta[mi];

      const pos = new Float32Array(nv * 3);
      for (let i = 0; i < nv * 3; i++) {
        pos[i] = mn[i % 3] + (dv.getUint16((vo + i) * 2, true) / 65535) * sc;
      }

      const idx = new Uint16Array(nf * 3);
      for (let i = 0; i < nf * 3; i++) {
        const v = dv.getUint16((fo + i) * 2, true);
        if (v >= nv) throw new RangeError(`Mesh ${mi} (${name}): index ${v} >= ${nv}`);
        idx[i] = v;
      }

      const g = new THREE.BufferGeometry();
      g.setAttribute('position', new THREE.BufferAttribute(pos, 3));
      g.setIndex(new THREE.BufferAttribute(idx, 1));
      g.computeVertexNormals();

      const mat = new THREE.MeshStandardMaterial({
        color: meshColor(k, name),
        roughness: 0.55,
        emissiveIntensity: 0.25,
        side: k === 'saraf' || isOrg(k) ? THREE.DoubleSide : THREE.FrontSide
      });

      const me = new THREE.Mesh(g, mat);
      me.userData.side = meshSide(name);
      // ... set userData.gh / userData.hid ...
      me.visible = false;
      built.push(me); // NOT added to scene yet!
    }

    if (signal && signal.aborted) throw new DOMException('Aborted', 'AbortError');

    // Atomic commit to scene only after full layer succeeds
    for (const me of built) scene.add(me);
    return built;
  } catch (err) {
    disposeMeshes(built); // full rollback; zero scene or GPU leaks
    throw err;
  }
}
```

Stale-switch coordinator pattern:

```js
let activeLoadCtrl = null;
let activeLoadSeq = 0;

async function ensure(k) {
  const seq = ++activeLoadSeq;
  if (activeLoadCtrl) activeLoadCtrl.abort();
  const ctrl = new AbortController();
  activeLoadCtrl = ctrl;

  if (!MESH[k]) {
    showLoading('Memuat model…');
    try {
      await loadLayer(k, { signal: ctrl.signal });
    } catch (err) {
      if (err && err.name === 'AbortError') return; // superseded cleanly
      if (seq === activeLoadSeq && layer === k) showLoadError(k, err);
      return;
    }
  }
  if (seq !== activeLoadSeq || layer !== k) return;
  hideLoading();
  build($('q').value.toLowerCase().trim());
  pick('__all');
  if (k !== 'rangka' && !isReference(k) && !MESH.rangka) {
    loadLayer('rangka').then(() => { if (layer === k) refresh(); }).catch(() => {});
  }
}
```

*(In `loadLayer(k, { signal })`, if `LOADING[k]` is aborted before completion, delete `LOADING[k]` in `.catch()` so subsequent switches back to `k` initiate a fresh fetch; if a layer is already cached in `MESH[k]`, return `Promise.resolve()` immediately.)*

### 2.4 Startup Failure & WebGL Context Loss Resilience

Verified directly from Three.js r128 [`WebGLRenderer.js`](https://github.com/mrdoob/three.js/blob/r128/src/renderers/WebGLRenderer.js) and [Khronos WebGL 1.0 §5.15.2 *The Context Lost Event* / *The Context Restored Event*](https://registry.khronos.org/webgl/specs/latest/1.0/#5.15.2):

1. **CDN / Script Load Failure**: `index.html` loads `three.min.js` (cdnjs) and `OrbitControls.js` (jsDelivr). If either fails (offline, corporate firewall, CDN outage), `window.THREE` or `window.THREE.OrbitControls` is `undefined`, currently throwing an uncaught `ReferenceError` at line 662 and breaking the entire app (including sidebar navigation and clinical descriptions).
2. **`WebGLRenderer` Initialization Failure**: `WebGLRenderer` tries `['webgl2', 'webgl', 'experimental-webgl']`; if `getContext()` returns `null`, it throws `Error('Error creating WebGL context...')`.
   - **Pattern**: Gate 3D initialization behind `if (typeof THREE !== 'object' || typeof THREE.OrbitControls !== 'function')` and wrap `new THREE.WebGLRenderer(...)` in `try/catch`. Keep UI initialization (`setLayer`, `build`, `render`, search, theme, panels) independent of WebGL readiness so the anatomical catalog and descriptions remain 100% functional, while `#ld` displays a `role="alert"` fallback message in the viewport.
3. **Runtime Context Loss (`webglcontextlost` / `webglcontextrestored`)**:
   - Per WebGL 1.0 §5.15.2, the browser will **never** attempt restoration unless a `webglcontextlost` listener calls `event.preventDefault()`.
   - Three.js r128 `WebGLRenderer` registers internal `onContextLost` (calls `event.preventDefault()`, sets `_isContextLost = true`, causing `R.render()` to no-op) and `onContextRestore` (sets `_isContextLost = false` and calls `initGLContext()`, recreating internal caches so geometries/materials re-upload on subsequent renders).
   - **App-level handler**: Register app listeners on `#cv` for `webglcontextlost` (call `e.preventDefault()`, `cancelAnimationFrame(rafId)` to stop burning CPU, disable orbit interaction, show a `role="alert"` overlay explaining GPU context loss) and `webglcontextrestored` (hide alert, call `fit()`, restart the rAF loop, and announce restoration politely via `role="status"`).

## 3. W3C WCAG 2.2 Level AA Requirements for 3D Viewer & Split-Pane Controls

Authoritative normative source: [W3C WCAG 2.2 Recommendation](https://www.w3.org/TR/WCAG22/) (October 5, 2023; editorial update December 12, 2024), supplemented by [WAI-ARIA 1.2 Recommendation](https://www.w3.org/TR/wai-aria-1.2/) and [WAI-ARIA Authoring Practices Guide (APG)](https://www.w3.org/WAI/ARIA/apg/).

### 3.1 SC 2.5.1 Pointer Gestures (Level A) & SC 2.5.7 Dragging Movements (Level AA)

- **SC 2.5.1** ([WCAG 2.2 §2.5.1](https://www.w3.org/TR/WCAG22/#pointer-gestures), [Understanding 2.5.1](https://www.w3.org/WAI/WCAG22/Understanding/pointer-gestures.html)): *"All functionality that uses multipoint or path-based gestures for operation can be operated with a single pointer without a path-based gesture, unless a multipoint or path-based gesture is essential."*
- **SC 2.5.7** ([WCAG 2.2 §2.5.7](https://www.w3.org/TR/WCAG22/#dragging-movements), [Understanding 2.5.7](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)): *"All functionality that uses a dragging movement for operation can be achieved by a single pointer without dragging, unless dragging is essential or the functionality is determined by the user agent and not modified by the author."*
- **Critical normative nuance from Understanding SC 2.5.7 (*Relationship to keyboard accessibility requirements*)**: Keyboard alternatives (e.g., arrow keys on a splitter or canvas) satisfy SC 2.1.1, **NOT** SC 2.5.7. A clickable/tappable **single-pointer** alternative without dragging is independently required.

**Human Atlas gaps & concrete remediations**:

| Drag / Multipoint Feature | Current State | WCAG 2.5.1 / 2.5.7 Single-Pointer Alternative |
| --- | --- | --- |
| Pinch-to-zoom (2-finger) / wheel zoom | `#zi`, `#zo`, `#rs` buttons exist | Already compliant via single-click buttons. |
| 3D Orbit (1-finger / left-drag) & Pan (2-finger / right-drag) | Drag / multipoint only | Add compact single-pointer camera step controls (e.g., orbit left/right/up/down or cardinal preset views Anterior / Posterior / Left / Right / Top) in `#ctl` or a collapsible camera-pad popover; structure selection from `#list` already re-centers camera target. (Understanding 2.5.7 Example 1 explicitly cites directional buttons as the reference non-drag alternative for map/viewport navigation.) |
| Panel resizing (`#rz1` sidebar, `#rz2` description) | Drag only (collapse buttons `#sbt`, `#itg` exist) | Collapse/expand covers binary toggle, not resizing. Add single-click non-drag sizing controls—e.g., a compact size-preset cycle button (Compact / Default / Wide, or `−`/`+` step buttons in panel header or splitter control menu)—so pointer users who cannot drag can resize both panes. |

### 3.2 SC 2.5.2 Pointer Cancellation (Level A)

- **SC 2.5.2** ([WCAG 2.2 §2.5.2](https://www.w3.org/TR/WCAG22/#pointer-cancellation), [Understanding 2.5.2](https://www.w3.org/WAI/WCAG22/Understanding/pointer-cancellation.html)): For single-pointer functionality, at least one of *No Down-Event*, *Abort or Undo*, *Up Reversal*, or *Essential* must hold.
- **Implementation**:
  - Standard `<button>` controls use `click` (implicit up-event activation with abort-on-drag-out).
  - 3D canvas selection MUST fire strictly on `pointerup` using the Section 1.4 state machine: no selection state mutates on `pointerdown`; moving past the tap threshold, initiating a second touch, triggering `pointercancel`, or releasing outside `#cv`'s bounding rect cleanly aborts selection.

### 3.3 SC 2.1.1 Keyboard (Level A) & SC 2.4.7 Focus Visible (Level AA)

- **SC 2.1.1** ([WCAG 2.2 §2.1.1](https://www.w3.org/TR/WCAG22/#keyboard), [Understanding 2.1.1](https://www.w3.org/WAI/WCAG22/Understanding/keyboard)): *"All functionality of the content is operable through a keyboard interface without requiring specific timings for individual keystrokes, except where the underlying function requires input that depends on the path of the user's movement and not just the endpoints."*
- **SC 2.4.7** ([WCAG 2.2 §2.4.7](https://www.w3.org/TR/WCAG22/#focus-visible), [Understanding 2.4.7](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)): *"Any keyboard operable user interface has a mode of operation where the keyboard focus indicator is visible."* Understanding 2.4.7 also cross-references SC 1.4.11 Non-text Contrast (focus indicator contrast `>= 3:1` against adjacent colors).

**Concrete keyboard interaction map**:

| Component | Focusability & Keybindings | Spec / Pattern Rationale |
| --- | --- | --- |

| `#sysel`, `#q`, `#list` (`.it`) | Native `<select>`, `<input type="search">`, and `<button class="it">` are natively Tab/Enter/Space operable. Optional: `Escape` clears `#q`; keep `.it` focusable and scroll selected `.it.on` into view without hijacking focus during canvas mouse clicks. | Standard HTML controls satisfy SC 2.1.1 & SC 4.1.2 natively. |
| `#cv` (3D viewport) | Add `tabindex="0"` and handle `keydown` **directly on `#cv`** (never on `window` so `#q`, `#sysel`, `#rz1`, `#rz2` are never hijacked): `ArrowLeft`/`ArrowRight`/`ArrowUp`/`ArrowDown` orbit camera in fixed angular steps (e.g., 15°); `Shift+Arrow` pans; `+`/`=` and `-` zoom; `0` or `r` resets view; `Escape` clears selection (`pick('__all')`). | Three.js r128 `OrbitControls.listenToKeyEvents()` only pans; custom `#cv` `keydown` delivers full orbit + pan + zoom + reset without key-timing constraints. |

| Focus indicator CSS | Apply explicit high-contrast `:focus-visible` outlines (`outline: 2px solid var(--acc); outline-offset: 2px;` with inset or contrasting ring on `.on` inverted buttons, `#rz1`, `#rz2`, and `#cv`) and ensure `--acc` vs `--bg`/`--panel`/`--txt` meets `>= 3:1` in both light and dark themes. | WCAG SC 2.4.7 + SC 1.4.11; `index.html` currently defines zero custom `:focus-visible` styles and hides visual focus on custom `<div>` splitters. |

### 3.5 SC 4.1.3 Status Messages (Level AA)

- **SC 4.1.3** ([WCAG 2.2 §4.1.3](https://www.w3.org/TR/WCAG22/#status-messages), [Understanding 4.1.3](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)): *"In content implemented using markup languages, status messages can be programmatically determined through role or properties such that they can be presented to the user by assistive technologies without receiving focus."*
- **Normative live-region roles** ([WAI-ARIA 1.2 `status`](https://www.w3.org/TR/wai-aria-1.2/#status) & [`alert`](https://www.w3.org/TR/wai-aria-1.2/#alert)):
  - `role="status"` carries implicit `aria-live="polite"` and `aria-atomic="true"`. Authors SHOULD ensure a `status` element does not receive focus on update.
  - `role="alert"` carries implicit `aria-live="assertive"` and `aria-atomic="true"`. Authors SHOULD NOT require users to close an alert and should not move focus into it (use `alertdialog` only if interrupting focus is explicitly required).

**Concrete live-region split for Human Atlas**:

1. **Pre-mounted polite status region** (present in initial HTML before any JS mutation so screen readers reliably register it):
   ```html
   <div id="sr-status" class="sr-only" role="status" aria-live="polite" aria-atomic="true"></div>
   ```
   Announce (briefly, debounced for search input):
   - Layer loading started (`"Memuat model Sistem Otot…"`), and completed (`"Sistem Otot dimuat, 185 struktur."`).
   - Structure selected from 3D canvas or list (`"Dipilih: Tulang Lengan Atas."`) or cleared (`"Pilihan dibatalkan, menampilkan semua struktur."`).
   - Search filter summary (debounced ~400 ms: `"12 struktur ditemukan"` / `"Tidak ada struktur yang cocok"`).
   - View actions (`"Tampilan direset"`, `"Putar otomatis aktif"` / `"nonaktif"`).
2. **Error / critical alert region** (for `#ld` error state, CDN failure, WebGL init error, WebGL context lost):
   - Render error text inside a container with `role="alert"` (or update a pre-mounted `role="alert"` node inside `#ld`) while leaving the `"Coba lagi"` retry `<button>` in normal DOM tab order—do **not** force `focus()` onto the alert container.
